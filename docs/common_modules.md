# Common Modules
Cross-cloud common modules reside under terraform/modules/common

## Common Naming Module
Because certain resources have different naming requirements, the common module consumes name-related metadata and returns resource-specific structured names.

The naming module resides at terraform/modules/common/naming

- Name segments should be controlled and validated as much as possible
- Name component segments should be minimal in length while still providing value
- The naming module uses inferred naming profiles to determine which name structure to return
- Disclaimer: The naming module does its best to minimize name length but is not fully tested against all cloud provider resource types and makes no claims to be fully compatible with all cloud resources. Provider resource modules will be responsible for owning their own name restrictions.
  - If name length is exceeded, the caller should try shortening the `type` they are passing, review and shorten the defined `project.code`, consider removing `random_suffix` "if used" and "if possible," or consider adding `compact = true` for the affected resource.

Supported name profiles are inferred from the request:

- Standard
- Compact
- Compute

```
role supplied -> compute
compact = true -> compact
otherwise -> standard
```

### General-Resource (Standard)
`{cloud.code}-{account.code}-{project.code}-{environment.code}-{type}-{descriptor?}`

When present, insert `{region.code}-` before `{type}`. When present, append `-{descriptor}` after `{type}`. When requested, append `-{random_suffix}` after the descriptor or type.

### General-Resource (Compact)
`{cloud.code}{account.code}{project.code}{environment.code}{type}{descriptor?}`

When present, insert `{region.code}` before `{type}`. When present, append `{descriptor}` after `{type}`. When requested, append `{random_suffix}` after the descriptor or type. Compact names use the standard components without delimiters.

### Compute
`{cloud.code}{account.code}-{role.code}{region.id}{environment.id}{instance}`

## Context Inputs
Complete resolved objects:
- project
- cloud
- account
- environment
- region (use `global = true` flag to omit region)

These are authoritative, controlled upstream objects. Their shape and catalog values are validated in the caller/root `variables.tf` files; the naming module trusts them.

## Naming Inputs
- type - general resource type (user provided standard cloud resource acronym)
- descriptor - optional 3-10 character lowercase alphanumeric value for resource uniqueness
- role - compute role code
- instance - compute-only ordinal
- compact - optional general-resource flag
- random_suffix - optional general-resource flag; null and false disable it
- global - omits region for global resources

The module returns only the final rendered name string.

### Example
```
module "storage_name" {
  source = "../../common/naming"

  name_context  = var.name_context
  type          = "st"
  descriptor    = "common"
  random_suffix = true
}
```

## Validation
The caller/root validates context objects and catalogs. The naming module validates the naming request and profile combinations.

### General resources
- role must be absent
- type required
  - type: 2-10 alphanumeric characters; input may contain uppercase and rendered names are lowercase
- descriptor is optional
  - descriptor: 3-10 lowercase alphanumeric characters
- instance must be absent
- compact must be null/false for standard, or true to select compact
- random_suffix can be null, false, or true; it is ignored for compute names
- compact can be null, false, or true; it is ignored for compute names
- region can be absent for global resources

### Compute
- role is required
- role: 3-4 lowercase letters
- descriptor is not supported with the compute profile
- instance is required
  - instance: exactly two digits, 01-99
  - Caller owns instance allocation
- type is required but not rendered; it can contain values such as `ec2` or `vm`
- compact: is not rendered
- random_suffix: is not rendered
- global: is not rendered; compute names always include the provider-local region ID

### Random Suffix
When random_suffix = true
- Generated by the naming module with `random_string`
- Exactly 4 lowercase alphanumeric characters (`a-z`, `0-9`)
- No special chars allowed
- Stored and stabilized by Terraform state
- Each naming-module instance receives its own suffix
- No random resource is created when the selected profile is compute
- No Provider collision detection/retry logic
- Will not be rendered if profile is compute

### Responsibility Boundary
#### Caller owns:
- Resolving authoritative context objects
- Validating context object shape and approved catalog values in caller/root `variables.tf` files
- General-resource type
- Compute role
- Compute instance allocation
- Requesting compact or random_suffix
#### Naming Module owns:
- Selecting naming behavior
- Rendering the name
- Lowercase normalization
- Interface/combination validation
- Random suffix generation and lifecycle
#### Naming Module does not own:
- Provider lookups
- Environment/region mappings
- Resource counts or for_each logic
- General-resource ordinal numbering
- Provider-specific resource catalogs
- Silent truncation or hashing
